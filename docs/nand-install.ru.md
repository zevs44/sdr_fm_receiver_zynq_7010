# Установка в NAND: запись OpenWrt с SD-карты

Пакет `nand-install` добавляет `/sbin/nand_install`. Скрипт записывает
работающую систему, загрузчик, битстрим и ядро с SD-карты во внутреннюю
NAND платы.

**Идея принадлежит автору**: скрипт из его второго проекта
[`Antminer_S9_OpenWRT`](https://github.com/alexsys87/Antminer_S9_OpenWRT).
Этот пакет сохраняет его порядок записи и добавляет проверки.

## Что делает

| Режим | Что пишет |
|---|---|
| `--full` (по умолчанию) | корневую ФС в UBI, затем `boot`, `uboot`, `uboot_env`, `fpga`, `kernel` |
| `--system` | только корневую ФС; загрузчик не трогает |

Корневая ФС копируется из `/rom` — read-only squashfs работающей системы, а не
из overlay. Поэтому временные файлы и сама SD-карта не копируются.

## Защиты

1. **Условия.** Права root, загрузка с SD (не из NAND), все разделы NAND
   присутствуют в `/proc/mtd`.
2. **Входные файлы.** Наличие, сигнатуры и размеры (заголовок FSBL, uImage,
   gzip, FIT); каждый файл помещается в свой раздел; система помещается в
   раздел rootfs.
3. **Пробный запуск.** `--dry-run` выполняет все проверки, печатает план и
   создаёт метку на 10 минут. Запись без свежей метки запрещена.
4. **Подтверждение.** Без `--yes` скрипт требует ввести слово `INSTALL`.
5. **Блокировка.** `flock` не даёт запустить две установки одновременно.
6. **Два этапа.** Сначала система, затем загрузчик.
7. **Проверка чтением.** `mtd verify` сравнивает записанное с исходным файлом.
8. **Журнал.** Все шаги пишутся в `/tmp/nand_install.log` и на экран.

## Использование

Из консоли (загрузившись с SD-карты):

```sh
nand_install --dry-run          # проверить план, ничего не записывая
nand_install                    # спросит слово INSTALL
```

Из LuCI (если установлен `luci-app-commands`): раздел «Система → Команды»
содержит две записи — `NAND: dry-run` и `NAND: установка`. Сначала запустите
пробный запуск: установка работает только в течение 10 минут после него.

## Требования

- Разделы NAND в дереве устройства: `boot`, `uboot`, `fpga`, `uboot_env`,
  `kernel`, `rootfs` (см. DTS платы).
- Пакеты `mtd`, `ubi-utils`, `nand-utils` (ставятся как зависимости).

## Ограничения

- Скрипт не создаёт таблицу разделов и не меняет дерево устройства.
- Он не проверяет файловую систему после записи: это делают проверки сборки и
  загрузка платы.
- Неудачная запись загрузчика из NAND не восстанавливается: загрузитесь с
  SD-карты и повторите установку.
