# Проверка платы: диагностический скрипт `run-diag-board`

Скрипт собирает состояние платы Antminer S9 (Zynq-7010) в один журнал: систему,
память, каталог пользовательских скриптов, дерево устройства, радиотракт, звук,
NAND, сеть и службы. Каждая проверка печатает вердикт `PASS`, `FAIL` или `SKIP`;
итог — строки `TOTAL` и `RESULT`.

Один и тот же скрипт работает на плате и в QEMU во время сборки. Пользователь
запускает его с параметрами по умолчанию, конвейер — с профилем `--profile qemu`,
который пропускает проверки, требующие FPGA и NAND.

## Что нужно

- Образ, собранный после 2026-11-26: в нём есть пакет `board-scripts`,
  каталог `/myscripts` с правами `777` и скрипт `/myscripts/run-diag-board`.
- Для запуска через LuCI — пакет `luci-app-commands` (входит в образ).
- Права root: скрипт читает `/proc/mtd`, `fw_printenv` и запускает
  `nand_install --dry-run`.

## Обзор проверок

| Группа | Проверка | Ожидаемый результат | В QEMU |
|---|---|---|---|
| Система | `/etc/openwrt_release` с `DISTRIB_ID` | версия OpenWrt напечатана | да |
| Система | `/rom` смонтирован как `squashfs` | корень только для чтения, overlay поверх | да |
| Система | `MemTotal` не меньше 400 000 Кб | 512 Мб или 1 Гб | да |
| `/myscripts` | каталог существует, права `777` | запись разрешена пользователю | да |
| `/myscripts` | `run-diag-board` на месте и исполняем | скрипт запускается из образа | да |
| Дерево устройства | узлы `axi_i2s_adi@43c00000`, `fm-radio@43c60000`, `sound`, `audio_clock` | адреса совпали с `design_1.bd` | да |
| Дерево устройства | шесть меток разделов NAND в узле разметки | `boot`, `uboot`, `fpga`, `uboot_env`, `kernel`, `rootfs` | да |
| Дерево устройства | в `/proc/cmdline` нет `earlyprintk` | лишний параметр убран | да |
| Радио | `/dev/radio0` | драйвер нашёл устройство в FPGA | `SKIP` |
| Звук | карта `audio` в `/proc/asound/cards` | тракт ALSA и `simple-audio-card` поднят | `SKIP` |
| Звук, `--sound` | воспроизведение тона на J2 (PDM) | поток открывается, звук идёт на ΔΣ-ЦАП | `SKIP` |
| NAND | `/proc/mtd` с шестью метками | драйвер NAND и разметка загружены | `SKIP` |
| NAND | `/etc/fw_env.config` и `fw_printenv` | окружение U-Boot читается из `uboot_env` | `SKIP` |
| NAND | `nand_install --dry-run` | размеры сходятся, запись возможна | `SKIP` |
| Сеть | интерфейс `eth0` и адрес по DHCP | сеть работает | `SKIP` |
| Сеть | hostname `owrt-zynq7010-XXXX` | первичная настройка выполнилась | да |
| Сеть | `/etc/antminer-mac` | постоянный MAC создан | да |
| Сеть | `network.lan.proto = dhcp` | настройка сети применена | да |
| Службы | `/www/cgi-bin/luci` и `uhttpd` | веб-интерфейс доступен | `SKIP` для службы |

## Запуск

### Через UART

```sh
/myscripts/run-diag-board
```

Вывод идёт в консоль и одновременно в `/tmp/run-diag-board.log`. Журнал UART
(PuTTY, `All session output`) сохраняет тот же текст целиком.

### До загрузки: U-Boot

Этап загрузчика скриптом не покрывается. Прервать автозагрузку любой клавишей и
выполнить:

```
bdinfo
printenv
mmc info
fatls mmc 0:1
nand info
mtd list
```

Ожидаемо: `DRAM: … 1 GiB` или `512 MiB`; в `fatls` — шесть файлов, включая
`system.bit.gz`.

### Через SSH

```sh
ssh root@<адрес-платы> '/myscripts/run-diag-board --log /tmp/run-diag-board.log'
scp root@<адрес-платы>:/tmp/run-diag-board.log ./run-diag-board.log
```

### Через LuCI

`Система` → `Команды` → `DIAG: проверка платы` (или `DIAG: проверка платы со
звуком`). Кнопки создаёт `/etc/uci-defaults/91-board-scripts` при первой загрузке.

### Параметры

| Параметр | Значение |
|---|---|
| `--profile board` | профиль по умолчанию: все проверки |
| `--profile qemu` | без FPGA и NAND: проверки этих групп дают `SKIP` |
| `--log <файл>` | дублировать вывод в файл; по умолчанию `/tmp/run-diag-board.log` |
| `--sound` | добавить воспроизведение тона 1 кГц (около 5 секунд) |
| `--full` | добавить полные `dmesg` и `logread` |
| `-h`, `--help` | краткая справка |

## Как читать вывод

```
PASS  система: OpenWrt 25.12.6
FAIL  карта ALSA: нет карты «audio» в /proc/asound/cards
SKIP  разделы NAND: в QEMU NAND не эмулируется
TOTAL pass=17 fail=1 skip=4
RESULT: FAIL
```

- `FAIL` — проверка не прошла: образ или плата отличаются от ожидаемого.
- `SKIP` — проверка неприменима в этом профиле или в этих условиях; это не ошибка.
- Код возврата: `0` — ни одного `FAIL`, `1` — есть `FAIL`, `2` — неверные аргументы.

Строки `TOTAL` и `RESULT` — машиночитаемый итог: по ним конвейер принимает решение.

## Передача журнала

- По сети: `scp` из `/tmp` или из `/myscripts`, если указан `--log`.
- Через SD-карту: `mkdir -p /mnt/sd && mount -t vfat /dev/mmcblk0p1 /mnt/sd`,
  затем `cp /tmp/run-diag-board.log /mnt/sd/` и `umount /mnt/sd`.
- Журнал UART — файл, который пишет терминал; он содержит тот же вывод.

## Роль в сборке

Шаг `03 qemu smoke` конвейера загружает собранный образ в QEMU и запускает тот же
скрипт с профилем `qemu`. Шаг завершается ошибкой, если в журнале нет
`RESULT: PASS`. Поэтому релиз берёт только образ, диагностика которого прошла
целиком; отдельного набора проверок для конвейера нет.

## Ограничения

- QEMU не эмулирует FPGA и NAND: радио, звук и запись в NAND проверяются только
  на плате.
- Проверка звука подтверждает тракт до J2 (PDM). Внешний I2S на колодке J6
  появляется только после сборки собственного битстрима.
- Запись в NAND не выполняется: `nand_install` запускается с `--dry-run`.
- Уровни и фронты сигналов командами не измеряются — нужен осциллограф.

## Обновление

Новая проверка добавляется в скрипт `packages/board-scripts/files/run-diag-board`
одновременно с строкой в таблице этого документа. Проверки, применимые только к
плате, помечаются `SKIP` в профиле `qemu`; без этого сборка начнёт завершаться
ошибкой на каждом образе.
