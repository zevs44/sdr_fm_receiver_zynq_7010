# Проверка платы: диагностический скрипт `run-diag-board.sh`

Скрипт собирает состояние платы Antminer S9 (Zynq-7010) в один журнал: систему,
память, каталог пользовательских скриптов, дерево устройства, радиотракт, звук,
NAND, сеть и службы. Каждая проверка печатает вердикт `PASS`, `FAIL` или `SKIP`;
итог — строки `TOTAL` и `RESULT`.

Один и тот же скрипт работает на плате и в QEMU во время сборки. Пользователь
запускает его с параметрами по умолчанию, конвейер — с профилем `--profile qemu`,
который пропускает проверки, требующие FPGA и NAND.

## Что нужно

- Образ, собранный после 2026-11-26: оверлей `files/` поставляет каталог
  `/myscripts` и скрипт `/myscripts/run-diag-board.sh`.
- Для запуска через LuCI — пакет `luci-app-commands` (входит в образ).
- Права root: скрипт читает `/proc/mtd`, `fw_printenv` и запускает
  `nand_install --dry-run`.

Права `777` на каталог и скрипт ставит `uci-defaults` при первой загрузке
(`/etc/uci-defaults/91_board_scripts`). Если права не появились, выполните
`chmod 777 /myscripts /myscripts/run-diag-board.sh`. Если каталог существовал
раньше и в нём лежат ваши файлы, установка их не трогает: образ поставляет только
свой файл `run-diag-board.sh` и не очищает каталог.

| Система | `MemTotal` не меньше 400 000 Кб | 512 Мб или 1 Гб | да |
| `/myscripts` | каталог существует, права `777` | запись разрешена пользователю | да |

| Дерево устройства | узлы `axi_i2s_adi@43c00000`, `fm-radio@43c60000`, `sound`, `audio_clock` | адреса совпали с `design_1.bd` | да |

## Запуск

### Через UART

```sh
/myscripts/run-diag-board.sh
```

Вывод идёт в консоль и одновременно в `/tmp/run-diag-board.log`. Журнал UART
(PuTTY, `All session output`) сохраняет тот же текст целиком.

### До загрузки: U-Boot

Этап загрузчика скриптом не покрывается. Прервать автозагрузку любой клавишей и
выполнить:

```
bdinfo
printenv
mmc info
fatls mmc 0:1
nand info
mtd list
```

Ожидаемо: `DRAM: … 1 GiB` или `512 MiB`; в `fatls` — шесть файлов, включая
`system.bit.gz`.

### Через SSH

```sh
ssh root@<адрес-платы> '/myscripts/run-diag-board.sh --log /tmp/run-diag-board.log'
scp root@<адрес-платы>:/tmp/run-diag-board.log ./run-diag-board.log
```

### Через LuCI

`Система` → `Команды` → `DIAG: board check` (или `DIAG: board check with
sound`). Кнопки создаёт `/etc/uci-defaults/91_board_scripts` при первой загрузке.

### Параметры

| Параметр | Значение |
|---|---|
| `--profile board` | профиль по умолчанию: все проверки |
| `--profile qemu` | без FPGA и NAND: проверки этих групп дают `SKIP` |
| `--log <файл>` | дублировать вывод в файл; по умолчанию `/tmp/run-diag-board.log` |
| `--sound` | добавить воспроизведение тона 1 кГц (около 5 секунд) |
| `--full` | добавить полные `dmesg` и `logread` |
| `-h`, `--help` | краткая справка |

## Как читать вывод

```
PASS  system: OpenWrt 25.12.6
FAIL  ALSA card: no "audio" card in /proc/asound/cards
SKIP  NAND partitions: NAND is not emulated in QEMU
TOTAL pass=17 fail=1 skip=4
RESULT: FAIL
```

Строки проверок печатаются на английском: тот же вывод читают конвейер и
разбор журнала. Комментарии в скриптах остаются на языке проекта.

- `FAIL` — проверка не прошла: образ или плата отличаются от ожидаемого.
- `SKIP` — проверка неприменима в этом профиле или в этих условиях; это не ошибка.
- Код возврата: `0` — ни одного `FAIL`, `1` — есть `FAIL`, `2` — неверные аргументы.

Строки `TOTAL` и `RESULT` — машиночитаемый итог: по ним конвейер принимает решение.

## Установка в NAND и загрузка без SD-карты

Проверка выше подтверждает только возможность записи. Установка — отдельный
шаг. Нужны образ, записанный на SD-карту (`build.md`, «Запись на карту»),
и файл `uboot.bin` в FAT-разделе. Скрипт отказывает `--full`, если в `boot.bin`
нет драйвера NAND (признак `OnDie ECC`).

Из консоли платы, загруженной с SD-карты:

```sh
/sbin/nand_install --dry-run    # проверки и план, метка действует 10 минут
/sbin/nand_install --yes        # корневая ФС в UBI, затем пять разделов
```

Дальше:

1. Выключить питание и вынуть SD-карту.
2. Поставить перемычки режима NAND: `0 1 0 0` — **JP2 = 1, JP3 = 0, JP4 = 0**
   (`0` — шунт на контактах 1–2, `1` — на 2–3). Режим TF Card `0 1 0 1` ищет
   SD-карту и без неё останавливается.
3. Включить питание с работающим терминалом UART и сохранить журнал целиком
   (PuTTY: `All session output`).
4. Ожидаемые строки: SPL читает U-Boot из NAND по смещению `0x80000`; U-Boot
   выполняет `nandboot` — читает `fpga`, загружает битстрим, читает `kernel`,
   запускает ядро с `ubi.mtd=5`.
5. Если плата не стартует, вернуть режим TF Card (`0 1 0 1`), вставить SD-карту,
   загрузиться с неё и передать журнал UART вместе с состоянием индикатора.

Скрипт `nand_install` пишет в раздел `uboot` файл `uboot.bin` — U-Boot 2016.03
с зашитыми командами NAND-загрузки. `u-boot.img` (2025.01) используется только
на FAT-разделе SD-карты. Ровный красный индикатор не называет этап сбоя:
`PS_MIO37_LED_R` управляется со стороны PS и горит, пока PS не дошёл до консоли.

## Передача журнала

- По сети: `scp` из `/tmp` или из `/myscripts`, если указан `--log`.
- Через SD-карту: `mkdir -p /mnt/sd && mount -t vfat /dev/mmcblk0p1 /mnt/sd`,
  затем `cp /tmp/run-diag-board.log /mnt/sd/` и `umount /mnt/sd`.
- Журнал UART — файл, который пишет терминал; он содержит тот же вывод.

## Роль в сборке

Шаг `03 qemu smoke` конвейера загружает собранный образ в QEMU и запускает тот же
скрипт с профилем `qemu`. Шаг завершается ошибкой, если в журнале нет
`RESULT: PASS`. Поэтому релиз берёт только образ, диагностика которого прошла
целиком; отдельного набора проверок для конвейера нет.

## Ограничения

- QEMU не эмулирует FPGA и NAND: радио, звук и запись в NAND проверяются только
  на плате.
- Проверка звука подтверждает тракт до J2 (PDM). Внешний I2S на колодке J6
  появляется только после сборки собственного битстрима.
- Диагностика не пишет в NAND: `nand_install` запускается с `--dry-run`;
  установка описана выше.
- Уровни и фронты сигналов командами не измеряются — нужен осциллограф.

## Обновление

Новая проверка добавляется в скрипт `files/myscripts/run-diag-board.sh`
одновременно с строкой в таблице этого документа. Скрипты каталога получают
расширение `.sh` и права `777`. Проверки, применимые только к
плате, помечаются `SKIP` в профиле `qemu`; без этого сборка начнёт завершаться
ошибкой на каждом образе.
